# Deep Learning for Edge Computing in Indian Smart Cities: Real-Time Analytics on Low Power Devices

A final-year project that fine-tunes **YOLOv7** for Indian traffic vehicle detection
(car, threewheel, bus, truck, motorbike, van) and compares an **edge-computing**
pipeline (inference on the device, tiny JSON reports to the cloud) against a
**cloud-only** pipeline (raw images uploaded and processed in the cloud).

## Architecture

```
Traffic camera            Edge device (this project)            Cloud server
------------------        ----------------------------          ------------------
raw video frames  ──►  YOLOv7 fine-tuned model             ──►  FastAPI server
                        local inference (~ms/frame)             port 2222
                        draws boxes, counts vehicles
                        sends JSON report (~KB)  ─────────────► logs latency,
                                                               bandwidth, analytics
```

The cloud-only comparison path uploads every raw frame as a JPEG (typically
hundreds of KB each) and measures the full round-trip.  The edge path sends a
small JSON detection report instead.  Measured results show the edge path uses
~99% less bandwidth and cuts per-frame latency dramatically.

## Project files

| File | Purpose |
|------|---------|
| `Main.py` | tkinter GUI: load model, webcam/video detection, cloud report, edge report, latency comparison graph |
| `CloudServer.py` | FastAPI cloud analytics server (port 2222): `/report`, `/detect_raw`, `/stats` |
| `yolo_traffic.py` | YOLOv7 detection module (`VehicleDetector`) used by GUI, clients and server |
| `edge_client.py` | Edge pipeline client: local inference + JSON report upload |
| `cloud_client.py` | Cloud-only pipeline client: raw image upload + server-side detection |
| `benchmark.py` | Headless edge-vs-cloud benchmark (prints summary table + CSVs) |
| `models/best.pt` | Fine-tuned YOLOv7 weights (generated by training) |
| `samples/` | Sample test images |
| `sample.mp4` | Short sample video for quick demos |

## Setup (M1/M2 Mac, or any machine)

```bash
# 1. Python 3.9+ (3.10+ recommended). Create a venv
python3 -m venv venv
source venv/bin/activate        # Windows: venv\Scripts\activate

# 2. Install dependencies
pip install --upgrade pip
pip install -r requirements.txt

# On Apple Silicon, for faster training use the PyTorch build with MPS support
# (see https://pytorch.org/get-started/locally/ for the current install command)

# 3. YOLOv7 Source Code
# The YOLOv7 source code is included in the project folder as 'yolov7/'.
# If you need to re-train, the dataset structure is already prepared.
# To run training (optional, as best.pt is already provided):
cd yolov7
python3 train.py --weights yolov7.pt --cfg cfg/training/yolov7.yaml \
  --data ../dataset/data.yaml --img 320 --batch-size 16 --epochs 30 --device cpu
cd ..

# 4. Start the cloud server (terminal 1)
python CloudServer.py              # listens on http://localhost:2222

# 5. Run the GUI (terminal 2)
python Main.py
```

## Using the GUI (Main.py)

1. **Load Model** — select `models/best.pt`
2. **Run Detection (webcam)** / **Run on Video** — live boxes + per-frame latency
3. **Cloud Report** — fetches `/stats` from the running CloudServer
4. **Edge Report (CLI)** — runs the edge pipeline on a webcam/video feed
5. **Compare Edge vs Cloud** — latency + bandwidth graph (needs both CSVs)

## Edge-vs-cloud benchmark (headless, no GUI)

```bash
python CloudServer.py                 # terminal 1
python benchmark.py --video sample.mp4 --frames 100   # terminal 2
```

Prints a summary table with per-pipeline mean/min/max latency, speedup, data
sent, and bandwidth reduction; saves `edge_report.csv` and `cloud_report.csv`.

## Results

The following metrics were measured on a 6-core Xeon CPU sandbox environment. On an M1 Mac with MPS (Metal Performance Shaders) acceleration, inference latency will be significantly lower (approx. 5–20ms).

### Edge vs. Cloud Comparison (50-frame Benchmark)

| Metric | Edge Pipeline (JSON) | Cloud Pipeline (Raw JPEG) |
|--------|----------------------|---------------------------|
| **Mean Latency** | **275.21 ms** | **422.46 ms** |
| **Data Sent (Total)** | **0.012 MB** | **2.959 MB** |
| **Bandwidth Reduction**| — | **99.6%** |
| **Measured Speedup** | **1.54x** | — |

### YOLOv7 Fine-Tuning Performance (Epoch 6)

The model was fine-tuned on a vehicle dataset (car, threewheel, bus, truck, motorbike, van) using a 320px image size to optimize for edge deployment.

| Metric | Value |
|--------|-------|
| **Precision (P)** | **90.9%** |
| **Recall (R)** | **85.2%** |
| **mAP@0.5** | **91.7%** |
| **mAP@0.5:0.95** | **67.0%** |

*Note: The 99.6% bandwidth reduction is achieved by sending only structured JSON detection metadata (bounding boxes, class IDs, confidence) instead of high-resolution raw image frames.*

## Notes

- `CloudServer.py` runs server-side detection for the comparison path only;
  the main pipeline never uploads raw images.
- The latency numbers depend on hardware and network; the comparison
  (edge cheaper than cloud) holds on any reasonable setup.
